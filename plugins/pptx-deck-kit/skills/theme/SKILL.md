# 資料の見た目を決める（テーマ）

資料の見た目は、テーマのファイル（`theme.json`）に書く。利用者には JSON もファイルの場所も見せず、話して決める。決めたら、見本のページを見せて確かめてから保存する。

以下の `<plugin>` は `${CLAUDE_PLUGIN_ROOT}`（このプラグインを入れた場所）。

## 置き場所

| 置き場所 | 効く範囲 |
|---|---|
| `~/.claude/pptx-deck/theme.json` | その人のすべての資料 |
| プロジェクトの `.claude/pptx-deck/theme.json` | そのプロジェクトの資料だけ（チームで共有できる） |

優先は、build.js の指定 ＞ プロジェクト ＞ 個人 ＞ プラグインの既定。テーマに会社の色があれば、build.js に書いた色より会社の色が勝つ。書ける項目と範囲は `<plugin>/skills/pptx-deck-design/references/tokens.md` の「テーマの設定の項目」の表。既成のテーマは `<plugin>/skills/pptx-deck-design/assets/themes/`（standard・corporate・pitch）。

## A. 設定が無いときに、最初の1回だけ聞く

pptx-deck-design で資料を作り始めるとき、個人にもプロジェクトにも `theme.json` が無ければ、作る前に1回だけ聞く（AskUserQuestion が使えればそれで、無ければ文で）。

> 資料の見た目（色・ロゴ・フッター）はどうしますか？
> ① 会社のテンプレート（pptx）がある → ファイルを渡す
> ② 会社の色とロゴだけ決める → 色とロゴを伝える
> ③ おまかせ → 題材に合わせて毎回選ぶ

- ①②なら、続けて「すべての資料に効かせるか、このプロジェクトだけか」を聞き、下の B の手順で作る
- ③なら `{"mode": "auto", "note": "おまかせ（題材に合わせて毎回選ぶ）"}` を個人の場所に保存し、以後は聞かない
- 「今回はおまかせで」「急ぎで」と言われたら、保存せずに今回だけ題材で選んで進める（次の資料で、また聞いてよい）
- `mode` が `auto` のファイルがあるときは聞かない

## B. 作る・変える

1. 頼まれた内容から、テーマの JSON を組み立てる。今のファイルがあれば読み、頼まれた所だけ変える
   - 会社の pptx を渡されたら：`python3 <plugin>/skills/pptx-deck-design/scripts/theme_from_pptx.py <pptx> <一時の theme.json> --logo-out <保存先のフォルダ>`。背景（画像）、文字の置き場所、章ナビ、ページ番号の形まで読む。出力に並ぶレイアウトの名前を見て、選ばれた表紙・章扉・本文が違えば `--cover`・`--chapter`・`--content` で選び直す。「デザインはスライドに直接描かれている」と出たら、渡された pptx を画像にして（render_pptx.sh）、表紙・章扉・本文にあたるスライドの番号を `--cover-slide`・`--chapter-slide`・`--content-slide` で指定して読み直す（本文のスライドは、上下左右の端の飾りだけを使う）。`.thmx` からは色と書体しか読めないので、背景も要るときは pptx か potx をもらう。どの色を強調の色に当てたか、何を読み取れなかったか（本文の背景を使わなかった理由など）を利用者に伝える。見本の画像を作ったら、渡された pptx と見比べる
   - 背景・飾り・ヘッダー・章ナビ・帯の高さを言葉で頼まれたら：`master`・`nav`・`footer.height`・`layout` に書く（項目は tokens.md の「飾りの層」「章ナビ」）。模様や背景の画像は、利用者の画像ファイルを theme.json と同じフォルダへ写して使う。章ナビを付けるときは、build.js の `createDeck` の `nav` に章の名前も書く
   - 色だけなら `colors.emph`（強調の色）を中心に。「緑」のような言葉なら、6桁の色に直して伝える（例 `00806E`）。ロゴは画像のファイルを受け取り、theme.json と同じフォルダへ写して `footer.logo`・`cover.logo` に相対パスで書く
   - 「文字を大きく・小さく」は `sizes`。テーマで下げられる下限（題 20pt、リード 18pt、やや大きい文字・名前・本文・注 14pt、主役の値 24pt）より小さくは頼まれてもしない（下回る値は部品が下限に直して警告する）。理由を一言添える
2. 保存する前に見本を見せる：
   - `node <plugin>/skills/theme/scripts/theme_preview.js <一時の theme.json> <一時の preview.pptx>`（表紙・章扉・棒グラフ・工程の流れの4ページ）
   - `bash <plugin>/skills/pptx-build-sync/scripts/render_pptx.sh <preview.pptx> <出力フォルダ> 70`（PowerPoint が使えなければ前に `RENDER_WITH=libreoffice` を付ける）
   - 画像を自分で見て、崩れ（はみ出し・読めない色の組み合わせ）が無いことを確かめてから、利用者に見せる
3. **見本の画像を利用者に見せ、「この見た目でよいか」の返事をもらってから保存する。** 自分で見て問題が無くても、返事の前に保存しない（色やロゴの好みは利用者が決める）。画像はパスを伝え、表示できる場ならその場で見せる。返事を待ったまま資料づくりに進まない。直したいと言われたら 1 に戻る。利用者が「確認なしで進めて」と言ったときだけ、見せずに保存してよい
4. 保存したら、どこに保存したか（「すべての資料」か「このプロジェクト」か）を一言で伝える

## C. 今の設定を見せる

個人とプロジェクトの theme.json を読み、効いている設定を言葉で短く伝える（色・書体・文字の大きさ・フッター・ロゴ・どのファイルが効いているか）。頼まれたら theme_preview.js で見本も見せる。

## 変えられないもの

テーマで変えられるのは見た目だけ。1ページ1メッセージ、見る所は1か所、マス目に文を積まない、文字の下限は変えられない。本文のページを濃い地にすることもできない（図が薄い地を前提にしている。表紙・章扉は濃くできる）。頼まれたら、理由を伝えて、帯や飾りで色を出す形を提案する。チームの決まり（`rules.md`）を足したいと言われたら、同じ置き場所の `rules.md` に書く（pptx-deck-design の「始め方」の0）。

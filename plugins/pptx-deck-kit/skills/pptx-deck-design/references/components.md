# 部品の組み方

関数は `assets/deck-parts.js`（`createDeck(pres, opts)` が返す）。引数の詳細は各関数の先頭のコメントにある。使い方の見本は `assets/sample-*.js`（グラフ・図解・流れ図・2軸・高密度の5本）。

## 比較の表 — `compareTable`（数値・評価・選択の表の既定）

見出しの下の線1本と、行の間の薄い細線・余白で組む表（2026-11-24 に、行に背景色を敷く帯の形をやめた）。戦略コンサル（McKinsey・BCG・Bain）の表の作法のうち、情報設計の部分を取り入れた（2026-11-08 に公開デッキを調べた結果。要点は本節の各項目）。

- 行の全幅に背景色を敷かない（帯の表・縞模様は禁止）。見出しと本文は線1本（1pt 灰）で分け、行の間は薄い細線（0.5pt）と余白で分ける。縦線・外枠・格子・見出しの塗りは使わない
- 数値だけが縦に並ぶ列は、見出しごと右揃えになる（自動）。行ごとに単位の違う評価表・文字の列は左揃え。列の `align` で指定もできる
- 決め手のセルは `{ text, focus: true }`。そのセルだけ薄い塗りと枠が付き、数値は 22pt、短い語（全角12字まで）は本文＋3pt になる。長い文は大きくならない
- 列見出し（選択肢名・対象名）は 19pt bold（推奨の列は ink、ほかは soft）。単位は見出しか行見出しの括弧に一度だけ（「年間の費用（万円）」）。見出しの2行目の `sub` は使わない（警告が出る）。セルは数字だけ
- 数値は右揃え（`align: "right"`）、文字は左揃え
- 群（効果／費用と手間など）は行の `group`。群の間は少し広い余白、群名は帯の上に 19pt bold（soft）
- 「判断」の行（`judge`）は使わない（種類の違う行。使うと警告）。結論は、リードか、表の右の空きに置く（`note: { head, body }`。枠なしの文字。表を引き伸ばして空きを埋める代わり）
- 現状は比べる基準の列（`base`）。見出しと値を soft にする
- 強調は1ページ1か所。推奨の列（`strong`＋`tag: "推奨"`）は列全体を ink 1.75pt の枠で囲む。選ぶ行（行の `strong`）は帯を濃くして ink の枠。太字にするのは選択肢名と決め手の値（`{ text, bold: true }`）だけ。中位の値を大きくしない
- 推奨案の弱点も、他の値と同じ濃さで見せる（隠すと最初に突かれる）
- 評価の記号: 測れる軸（費用・期間・件数・割合）は数値で書く。判断の軸だけハーベイボール（`{ ball: 0〜4 }`）。根拠の文は添えない（決まり20。添えると警告）。凡例は `legend: true` で表の左上に1行
- 割合は横棒で長さを見せてよい（`{ bar, max, text, main }`。主役だけ ink、他は bar）
- 何の表か・単位・時点は、表の上に `figHead` で1行か、行見出しの列の見出し（`labelHead`）に書く
- 大きさ: 5行×4列まで（超えると警告）。目安は3行×3列
- 行の高さ: 部品が本文の下端（`bottom`）まで等しく広げる（1行の高さは 1.8 まで）
- 文字: 値は濃い 20pt（`fs`）。行の名前と列の見出しは、控えめな 19pt（`fs` − 1。soft の色。行の名前は太字にしない）。小さくしない。入らないなら行を減らす
- セルに入れてよいもの: 数値、ゲージ（`{ bar: 値, max }`）、評価の丸（`{ ball: 0〜4 }`。満たす・一部・満たさない）、星（`{ stars: n, max? }`）、全角4字までの短い札。文字は入れない（警告が出る）。評価の丸に根拠の文（`text`）を添えない
- 種類: 1つの表には、同じ種類の値だけ（数値と評価の印を混ぜると警告）
- 幅: 列の幅は中身から決め、余った幅は列に配って本文の幅まで広げる（横の結論 `note` の分は残す。`fit: false` で等分、`labelW`・列の `w` で固定）
- 違い: 行の中で、ほかの列と同じ値は薄くなる（`dimSame: false` でやめる）。セルは短い語か数値（全角12字まで）
- 行が少ないときも、行を足して埋めない。部品が行の高さを広げる。表の上端 `y` を下げて中ほどに浮かせない

## 補足の `sub` は使わない（2026-11-24）

`compareTable` の列と行、`bizModel` の主体、`tamSamSom` の行の `sub` は、使うと警告が出る（古い資料を読むために残してある）。要る中身は、名前に書く（列の見出しは `"\n"` で2行にしてよい）。`metricBars` の `unit` は、名前の後ろに「（単位）」として同じ行に出る。`tamSamSom` の `what` は、円の中に1回だけ出る（右の行には出さない）。

## 指標ごとの棒 — `metricBars`（単位や桁の違う数値の比較）

- 単位や桁の違う指標（時間・費用・期間など）で、いくつかの対象を比べるときに使う。数値を表に並べない
- 行＝比べる対象（3〜5）、列＝指標（2〜4）。列ごとに尺度をそろえた横棒と値。同じ列の棒は、縦に長さを見比べられる
- `focus` で主役の行（棒が強調の色、名前が濃い）。`key: [行, 列]` で、決め手の値1つを大きく（36pt・強調の色）
- 単位は、指標の見出しの後ろ（`unit`。「（時間／月）」の形で同じ行）に1回だけ

```js
d.metricBars(s, { items: ["今のやり方", "他社の製品", "自社の製品"], focus: 2, key: [2, 0],
  metrics: [{ label: "事務の時間", unit: "時間／月", values: [20, 4, 2] }, { label: "3年間の費用", unit: "万円", values: [0, 840, 108] }] });
```

## 塗りブロックの表 — `blockTable`（使わない。2026-11-24 に禁止）

文字を入れる表は使わない（呼ぶと警告が出る）。全部読まないと分からない表は、表の意味をなさない。項目ごとの箇条書き（`points`）か図にする。以下は、古い資料を読むための記録。

数値・評価・選択の表には使わない（`compareTable`）。セルが「見出し＋2〜3行の説明」の定性のマトリクス（ルールと例外、対策のマトリクス、ファネルの下の段階ごとの表）にだけ使う。溝は列の間 0.06、行の間 0.16（行の向きに読ませる）。列見出しは bold ink。


格子の表・帯の表・`addTable` は使わない。表はすべてこの関数で組む。

1. セルは独立した矩形。tint（F4F6F9）、枠なし、角丸なし
2. セルの間は白い溝。密 0.06〜0.1／標準 0.12〜0.15／行を強く分ける 0.18〜0.2
3. 列見出しは塗らない。gray の bold を最初の行の少し上に置き、下線を引かない。見出しは1段だけで、下に定義の小行を入れない
4. 行見出し（左端）も塗らない。ink の bold、上下中央
5. セルの中は2段: 見出し（bold ink）＋6pt の空行＋説明（regular soft）。文章を流し込まない
6. 同じ帯のセルは同じ幅・高さ。行は一番高い行にそろえる
7. 強調は1ページ1か所（1セルか1列）: `strong`（E3EAF4）か `frame`（ink 2pt 枠）、またはその両方。tint と E3EAF4 は近いので、塗りだけで3秒で目に入らなければ枠を重ねる（同じ1か所への強調なので「1種類」のまま）。強調セルに小見出し（`tag`）を置いてよい
7-2. 1行だけのセル（見出しも説明もない短い値）は bold にしない。表の全セルが bold になると強調が消える
7-3. 選択肢が行に並ぶ表で「選ぶ1行」を示すときは、行に `strong: true`（セルを濃い塗り・bold・1段大きく、行全体を ink 2pt の枠1本で囲む）。セルごとに枠を付けない。これも1ページ1か所の強調に数える
8. 問題のセルは `problem`（白地＋赤枠＋赤字）。あるべき側を `strong` にして対にする
9. 面（`journeyMap` の After の面など）の上では `onFace` でセルを白にする
10. 該当なしは `null`（破線の空枠）。全部を埋めない。「未設定」「要確認」と書かない
11. 例示の列は `example`（白＋細枠）、参考・基準の列は `ref`（見出しを一段弱く）
12. 複数の列にまたがる値は `span` で1本の帯にする
13. 数値を見せるセルは `num`＋`unit`（22pt の数字）
14. 例外や注意はセルの中に書き、表の下に別記しない

表の例外: 記号や数字が主役で行数の少ない表（星取など）だけ、塗らずに行の上に 0.75pt の細線（`hline`）を引いてよい。

## 段階の道 — `roadmap`（計画・ロードマップ）

- 横の道に、段階の駅を3〜6つ並べる。駅の丸の中に絵（`icon`。無ければ番号）、上に時期、下に名前
- 駅の下に、次へ進む条件を値で置く（`kpis: [[値, 何の値か, 絵?]]`。4つまで。「値　何の値か」を1行で書き、本文の大きさで箱の幅に入らないと警告。4段階なら全角10字ほど）
- 持ち帰る値は `{ key: true }` を付ける（`["月6万食", "販売数", { key: true }]`）。値を大きく書き、何の値かをその下に置く。全体で2つまで。リードが名指しする基準や目標は、これで大きくする
- いちばん下に、資金や体制の帯（`bands: [{ from, to, label, strong? }]`）
- 見る所の段階を1つだけ `strong`（丸を強調の色で塗る。白い絵 `<名前>-w.png` があれば、それを使う）
- 続きのページでは、`spot: r => r.col(i)` で、その段階の列だけを残せる。2つ以上の段階にまたがる帯は、1段階の列には含まない。帯の段階をすべて残すときは、`col` を足した矩形を渡すと帯まで残る
- 線の絵（`pic-search`・`pic-launch`・`pic-people`・`pic-building`・`pic-yen`・`pic-box`・`pic-contract`・`pic-calendar`・`pic-laptop`・`pic-bubble`・`pic-star`・`pic-pie`・`pic-play`・`pic-umbrella`）が `icons/` にある

```js
d.roadmap(s, { stages: [
  { name: "検証", when: "〜2027年2月", icon: "pic-search", kpis: [["過半数", "同じ悩みの人", "pic-people"]] },
  { name: "個人に展開", when: "2027年6月〜", icon: "pic-people", kpis: [["300人", "週次の利用者", "pic-people"]], strong: true },
  { name: "企業と試行", when: "2028年4月〜", icon: "pic-building", kpis: [["1社以上", "有償移行の合意", "pic-contract"]] },
], bands: [{ from: 0, to: 0, label: "自己資金" }, { from: 1, to: 1, label: "プレシード", strong: true }, { from: 2, to: 2, label: "シード" }] });
```

## 段階×観点の全体像 — `journeyMap`（使わない。2026-11-24 に禁止）

マス目に文を積む形なので使わない（呼ぶと警告が出る）。`roadmap` で描く。以下は、古い資料を読むための記録。


- 進め方・実施要領・ロードマップの全体像を、1枚で高密度に見せる（元にしたのは振り返り報告書の「改善の詳細（全体フロー）」）
- 上に段階の矢羽（6〜7段階）。下に観点の行を5〜7行（期間・費用・体制・達成目標・判断の指標・成果物・アンチパターン など）
- 段階の境に会議の縦の破線を表の上から下まで通す。審査ゲート（新しく設ける判断）は赤、既存の会議は灰、最大の分岐点だけ太く。名前は矢羽の上に同じ高さで
- 体制の行は `{ people: [[役割, 社外?]] }` で人のピクトを人数分。社外は灰
- 2段階以上にまたがるもの（開発を続ける期間など）は `{ span: n, text, frame: true }` で会議の線の上に重ねる
- 注意を示す行（今回やってしまったアンチパターン）は、行の先頭に「!」で赤字にする。凡例の代わりにリードで「赤字は〜」と言う
- セルの文字は 8.5pt。1行に入るのは約11字なので、長い行は語の切れ目で `\n` と全角スペースの字下げで折る（1〜2文字だけの行を作らない）
- 本文の下端（6.6）を越えて 7.0 まで使ってよい（高密度の全体像のページだけ）。リードは1行に収める

## 多段の樹形図 — `logicTree`

- 原因・要因・課題の分解は、これを既定にする。左の問題から右へ、1つのノードから2〜3本ずつ広がる（1 → 3 → 9 が目安。深さ 3〜4、葉は 12 前後まで）
- 列の見出し（`heads`）で各段の意味を言う（「問題」「直接の原因」「根本の原因」）
- ノードは「言い切りの見出し」＋「根拠の短い説明（数値）」の2行。葉は1行ずつに収まる長さにする
- 手を打つべき根本の原因だけ `problem`（白地＋赤枠＋赤字）。結論・対策の起点を示すときは `strong`。1枚で使う強調は1種類
- 線は灰 1pt の鉤線。親の右から、子の左へ

## KPIツリー — `kpiTree`

- 指標を掛け算・足し算で分解し、どこが増えた・減ったかを見せる。親が子の積や和になる（数値がつながる）ときだけ使う。文で原因をたどるなら `logicTree`
- ノードは「名前・値・増減」。分かれ目の丸に子の結び方（`op`："×" "＋" "−" "÷"）を書く。子が2つ以上あって `op` が無いと警告
- 見る所は1つだけ：悪い所は `problem`（赤枠、増減を 36pt の赤）、効く所は `strong`（強調の色の枠、増減を 36pt の強調の色）。他の増減は灰
- 葉は6個まで、段は4段まで。値と増減が箱の幅に入らないと警告（単位を「万」「億」にして縮める）
- 線は灰の鉤線。親の右から、子の左へ

## RACI（役割の分担） — `raciTable`

- 作業（行）×担当（列）のセルに、R・A・C・I の印だけを置く。セルに文字は入れない
- 印の濃さ：A＝決める（強調の色の塗り）、R＝実行する（灰の濃い塗り）、C＝相談を受ける（白抜き・濃い線）、I＝報告を受ける（白抜き・薄い線）。意味は表の上に1行の凡例で出る（`legend: false` で消す）
- A は1つの作業に1人。A がいない・2人いる行は `problem` を付けて赤枠で見せる（作業名の右に「A がいない」を部品が書く。`note` で替える）。付けずにあると警告
- 担当は6列まで、作業は8行まで。表の形は `compareTable` と同じ（見出しの下に線1本、行の間は薄い細線。縦線・外枠は使わない）

## プロジェクトのガント — `projectGantt`

- 計画・スケジュールは、これを既定にする。グループ（大項目）と作業（小項目）の2段で 10〜20行
- 計画を示す図なので、帯は同じ太さ。リードが言う作業の帯だけ `task.focus: true` で強調の色にし、他は灰になる（決まり23）。見る所が無いときだけ、すべて同じ色（ink）
- 描かないもの: 遅れ、予定と実績の重ね、今日の線、ひし形の節目、期間を示すグループの線、審査ゲート・会議の線、重要な作業の色分け
- グループの行は全幅に薄い塗りの帯と太字の名前。作業は字下げして、担当の列を付ける。帯は日単位（"2027.02.17"）
- 遅れや進み具合を言いたいときは、別のページで同じ図を `echo` で背面に敷き、前面の `messageBox` で言う
- 20行を超えるなら、グループごとに2枚に分ける。行の高さが文字（密な図なので作業名 16pt・グループ名 18pt）の1行より低くなると警告が出る

## 経緯のガント — `timeline` / `drawGantt`

- 過去の経緯を区分の帯で見せる俯瞰用。計画・スケジュールには `projectGantt` を使う

- 行＝区分（区分色の帯、枠なし）、列＝月。年度と四半期の目盛り。行の区切りの罫線は引かない
- 節目は赤の縦破線＋ひし形＋赤字のラベル。グリッド線の上に置き、帯の背面に描く。節目の強調はこれだけにし、列の塗りや帯の色替えを重ねない
- 最大の分岐点だけ線を太くする（`milestones[].width: 3.5`、他は既定の細さ）。記号（★など）は使わない。節目のラベルは注の大きさの赤字。ラベルは既定で線の左、入らなければ自動で右に置く
- 目盛り: 既定は年度と四半期。構成案が暦の年月で書かれ、月単位の差を読ませるときは `axis: "month"`（暦年と月）
- 予定と実績: 行に `plan: [[from, to], ...]` を渡すと、上に予定の破線の帯、下に実績の帯を描き、凡例を行ラベル列の上に置く。帯の外の短い注記は `notes: [[月, 文字]]`
- 行が少ないときは行の間を広げて本文の下端まで使う。重ね技で下に吹き出しの場所を残すページ（とその元のページ）は `compact: true` で止め、両ページで同じ指定にする
- 上位の行を最上段に置き、下で詳細化する。出来事・判断・対象を同じ行に混ぜない
- 帯の中に文章を書いてよい。濃い区分色の帯だけ白文字
- 期間の範囲は soft 1pt の破線で囲み、名前を中に置く

## 重ね技 — `echo` / `overlay` / `messageBox` / `callout`

1つのデータや議題に複数ページで触れるときは、新しい図を起こさず、同じ図を背面に敷いて前面に重ねる（SKILL.md「同じデータ・議題を複数ページで扱うとき」）。図を動かさず・縮めない。

- `echo(s, drawFig, { area, transparency, spot, keep, check })`: 図を描く関数を渡すと、同じ図を描いてから白の半透明で覆う。`drawFig` は1枚目と同じもの
  - `spot: {x, y, w, h}`（か、図の戻り値から矩形を返す関数）: 見る所の矩形。そこだけ覆わず、元の濃さで残す。形が矩形1つで囲めないときは `{ parts: [矩形, …] }`。境目が文字・区分名の途中を通らないよう、要素の外側にそろえる。`only` を持たない部品でも使える
  - `keep: (s, r) => {}`: 覆いの上に、前面で指す要素（主役の棒、値のラベル）だけを元の濃さで描き直す。`r` は `drawFig` の戻り値（部品の戻り値を返しておく）
  - ネイティブのグラフ（`barChart`）は、1本だけを描き直せない。重ね技で前面から棒を指すデータは、最初から図形の部品（`colBars` / `hBars` / `ribbonBars`）で描く
  - `check: true`: 覆いと前面を外して描く確認用。画像にして `scripts/figure_diff.py` で1枚目と比べ、差が 0 なら外す
- `messageBox(s, { x, y, w, h, head, body, to | toRange, refKey })`: 分かったこと・結論を前面に置く白い箱（ink 1pt の枠、弱い影）。`to` で指す1点へ赤の線と小さな丸。`toRange: [[x1, y], [x2, y]]` で範囲（2020〜2024年など）を赤の線で括って指す。見出しと本文の行数が高さ `h` に入らないと警告（`h` を広げるか、文を縮める）
- `callout`: 番号つきの論点や問題を前面に置く（赤枠）。複数の論点を1枚に重ねるときに使う
- 前面の要素は、薄くした下の図の上（話に使わない区分の上か空いた側）に置き、図の主役（指す棒・帯）を隠さない。1枚目に場所を空けておかない
- 同じ図の続きではないページ（`echo`・`series` を使わないページ）の `messageBox`・`callout` は、図の要素を指す注釈（`to`・`toRange`）にする。図に無い数値や別の内訳を載せた補足の箱は置かない（1つの図にまとめるか、ページを分ける。SKILL.md の4）。指さない箱に図に無い数値があると警告

| 型 | やり方 |
|---|---|
| 薄く敷いて前面に置く | 同じ関数・同じ引数で描き、`overlay` で白く薄くし、`callout` や結論の箱を前面に置く |
| 図だけ → 分かったこと → 根拠 | 1枚目は図だけ。2枚目に同じ図を薄くして結論を該当箇所に重ねる。根拠は次のページ |
| 追記で積む | 図と枠の位置を固定し、ページごとに行を足すだけ。引き継いだ行は灰、足した行は黒 |
| 同位置同寸の After | 前のページと同じ位置・大きさ・縦軸最大で After を描き、ページ送りで差を見せる |

- 前面の囲みが下の図に半端に重なるなら、完全に覆う大きさにする
- 後で重ねる図は、先に事実のページで素のまま見せておく
- 図の座標とデータは定数にして、両ページから同じものを渡す

## 同じ図の続きページ — `series`

1つの図で2つ以上を言うときと、1つ目の図のある要素の掘り下げが1つの図に収まらないときに使う（SKILL.md の4）。図を1回書けば、言うことの数だけページが出る（1ページ1メッセージ。リードはページごとに1つ、見る所は前面の1つ）。

```js
const sol = d.series((s, x) => d.processFlow(s, { ...FLOW, ...x }));
sol.page({ title: "解決策の全体", lead: "…", focus: "上の3つの矢羽" });                       // 1枚目：図だけ
sol.page({ title: "記録の実現性", lead: "…", focus: "「記録する」の列",                      // 2枚目から：同じ図を薄く敷く
  spot: r => r.col(0),                                                                    //   見る所だけ元の濃さで残す
  box: r => ({ x, y, w, h, head: "1　記録できるか", body: "…", to: [...] }) });            //   前面にメッセージボックスを1つ
```

- 題は、同じ図で同じ話題を続けるときだけ同じにする。続きのページで扱う中身が変わるなら、題を変えるか、両方を含む名前にする（SKILL.md の7）
- `focus`（見る所）は全ページで書く。`spot` は見る所の矩形（図の戻り値から返す関数でよい）。`only` を持つ部品（`processFlow`・`cycleDiagram`・`bizModel` など）は `only` でもよい
- 続きのページは、ほかのページを挟んでもよい（`series` の戻り値を取っておき、後ろで `page` を呼ぶ）
- 本文の下端を越える図（`journeyMap`）は、`series(draw, { area: { y, h } })` で覆う範囲を渡す
- **前面の箱・札は、薄くした下の図の要素（矢羽・段・行・セル・棒・文字・図形）と「重ならない」か「丸ごと覆う」のどちらか。** 線（罫線・軸・矢印）は数えない。置き場所は戻り値の指定で作る：

  | 部品 | `cover(i, j)`（j を省くと端まで） | `below()` |
  |---|---|---|
  | `processFlow` | i〜j の工程の列（矢羽・所要・行） | 図の下の空き |
  | `roadmap` | i〜j の段階（時期から帯まで） | 図の下の空き |
  | `compareTable` | i〜j の列 | 表の下の空き |
  | `colBars` | i〜j の区分の列（値・棒・区分名） | なし |
  | `hBars` | i〜j の行（幅いっぱい） | 棒の下の空き |

  ```js
  box: r => ({ ...r.cover(1), head: "議題は部下が決める", body: "…" })   // 2列目から右を丸ごと覆う
  ```

- 一部にだけ掛かる指定は、部品が要素の外枠まで箱を広げる（`[deck-parts-fit]` の行で知らせる。警告には数えない）。広げた箱が指す点のすぐ横に来たら、引き出し線は引かない。広げると濃く残す所（`spot`・`from`・`keep`）や指す点に掛かるとき、まだ一部に掛かるときは**止まる（エラー）**。そのときは置き場所を変えるか文を縮め、どこにも置けなければ別のページにする
- `spot` の境目が、文字や図形の途中を通ると警告（半分だけ薄くなる）。`col`・`row`・`span` など、要素を丸ごと含む矩形を渡す
- 引き出し線は `from` と `to` で水平か垂直にする。見る所のすぐ隣の箱には、引かなくてよい
- 図が動いていないかは、`series(draw, { check: true })` で前面を外した画像を作り、`scripts/figure_diff.py` で1枚目と比べる

### 前面に2つ目の図を重ねる — `overlay`

**重ねる形（`overlay`）を使うのは、2つ目の図が1つ目の図のある要素の「掘り下げ」（その要素の内訳・種類別・その要素の中の詳しい数字）のときだけ。**別の事実・別の指標を続けて言うなら、別のページ（別の図）にする（例：残業の棒から、支払いの遅れの件数の札は出さない）。掘り下げが数値の比較のとき、1枚目の図を薄く敷き、前面の白い札に2つ目の図を描く。掘り下げる元の要素（`from`、必須）は濃いまま残し、部品が札へ矢印を引く。

```js
const market = d.series(s => d.colBars(s, { cats: ["2021年", "2025年", "2026年（見込み）"], series }));  // 1枚目の図。戻り値を返す
market.page({ title: "個食市場の伸び", lead: "…", focus: "年平均の成長率" });
market.page({ title: "個食市場の伸び", lead: "伸びの中心は主菜で、4年で+83%。", focus: "前面の主菜の棒と+83%",
  overlay: r => {                                                      // r は1枚目の図の戻り値
    const from = r.span(0, 1), x = from.x + from.w + 0.55;             // 掘り下げる元＝2021・2025年の棒。札はその右の、使わない区分の上
    return { from, x, y: 2.45, w: 12.73 - x, h: 4.15, title: "2021→2025年の伸びを種類別に（%）",
      ref: { value: 61, label: "個食の全体 +61%" },                     // 全体の値の基準線（左の棒の伸び）
      draw: (s, rect) => d.hBars(s, { ...rect.rows, rows: [...] }) };  // 縦棒なら d.colBars(s, { ...rect.cols, max, cats, series })
  } });
```

| 引数 | 意味 |
|---|---|
| `from` | 必須。掘り下げる元の要素。そこは元の濃さで残り（`spot` と同じ扱い）、部品が `from` から札へ矢印（水平か垂直）を引く。`colBars` の `span(i, j)`、`hBars` の `row(i, j)` で作る（境目が文字の途中を通らず、元の名前も渡る）。ほかの図は `{ x, y, w, h, name }`。無い・名前が無いと警告 |
| `x`・`y`・`w`・`h` | 札の位置と大きさ。本文の領域の中（はみ出すと警告）。話に使わない区分の上か空いた側に置き、`from` の横か上下に 0.3 以上空ける。薄くした下の図の要素には、重ならないか丸ごと覆う（`...r.cover(i, j)` で列・行ごと覆える。下端は区分名まで要るので 6.75 まで）。一部に掛かる指定は部品が広げる。**`from` に重なると止まる（エラー）** |
| `title` | 何の図か（単位・期間もここに）。1行。**掘り下げる元の名前か期間を入れる**（例「3月の増加320件の内訳」）。無いと、別の指標に見えるとして警告 |
| `draw(s, rect)` | 2つ目の図を描く。`rect.cols` は `colBars` に、`rect.rows` は `hBars` に展開して渡す。`ref` を使うときは、部品の戻り値を返す |
| `ref` | 省ける。`{ value, label }`。札の中の図に引く基準線（全体の値など）。名前には値を書く。`colBars` は横の線、`hBars` は縦の線になり、値の字の所は切れる。`colBars` は `max` を基準線の値より大きくする |
| `arrowAt` | 省ける。矢印の位置（横向きなら y、縦向きなら x） |
| `clear` | 省ける。ほかにも隠してはいけない下の図の要素の矩形。重なると警告 |

- 下の図の比べる相手を隠さない。区分が3つまでの図は `from` 以外の全部、それより多い図は主役の区分と1枚目のリードが名指しした区分（値）を隠すと警告。置けないなら、重ねずに別のページにする
- 前面の図に、見る所の値（36pt）を1つ置く。下の図の主役の値は、薄いので見る所に数えない。リードが言う数値も前面で大きくする
- 札の中の区分名が入らないと警告（名前を縮めるか、札を広くするか、`hBars` にする）
- 前面の文字の大きさと色は、本文の図と同じ決まり（18pt 以上、本文の色）
- 1枚目の図は本文の領域を使い切る。札の場所を空けるために `x1` などで狭めない
- `series` を使わず `base` と `echo` で描くページでは、`echo(s, drawFig, { spot: from })` の後に `d.frontCard(s, { from, x, y, w, h, title, draw })` を呼ぶ

## ビジネスモデル図 — `bizModel`

- 「誰が、誰に、何を渡すか。どこでお金が入るか」を1枚で見せる。個人と会社を列にした比較の表にしない
- 主体（人・会社・製品・場）を格子に置く（`cols`×`rows`）。利用者を上、事業者を下に置くと読みやすい
- 線は、水平・垂直と鉤線だけ。斜め線は使わない。同じ行・同じ列に無い主体は、直角に1回折ってつなぐ（下の主体の横から出て、上の主体の下へ入る。`via: "v"` で先に縦）。同じ2者の間の2本は `lane` で平行にずらす
- 矢印は、お金（円の中に ¥）、物やサービス（塗りの四角）、情報や権利（白抜きの四角）の3種類。印と名前は、いちばん長い線の真ん中に置く（横の線なら上か下、縦の線なら横。`at`・`labelW` で調整する）
- 強調はお金の入る矢印1本だけ（`strong`）
- 矢印がほかの主体の箱を横切ると警告が出る。主体の置き場所を変える
- 主体のアイコンは `icon`。外部の会社・製品は公式のアイコン、自社や一般の主体は汎用のアイコン

## 自作の図（全体の仕組みを俯瞰するインフォグラフィック）

部品に合う形が無いときは、build.js に図を描く関数を1つ書く。部品の表に中身を詰めない。

- 関数は `const draw = s => { …; return { block: i => 矩形, … }; }` の形にする。`d.series(draw)` に渡せば、続きのページで同じ図を敷ける。かたまりごとの矩形を返しておくと、`spot: r => r.block(i)` で見る所を残せる
- 描くのに使うのは `d.rect`・`d.T`・`d.segLine`・`d.icon`・`d.arrowR` と、色・余白のトークン（`d.C`・`d.TINT`・`d.TINT_STRONG`・`d.M`・`d.W`）。色と文字の大きさは `references/tokens.md` の範囲に収める
- 箱と箱をつなぐ線は、水平・垂直と鉤線だけ（`d.polyArrow(s, [[x, y], …], { color, width })`）。斜め線は使わない
- 多くの要素が1つへ集まる線・1つから分かれる線だけは、`pres.shapes.CUSTOM_GEOMETRY` の曲線（`points` の `curve: { type: "cubic", … }`）で束ねてよい
- 見る所のかたまりだけ、濃い塗り（`TINT_STRONG`）と ink の枠にする。ほかは薄い塗り、線は灰
- 小さな補足の文字（サブテキスト）を、かたまりごとに足さない。俯瞰の図は、形と名前で読ませる。そのページの主張に要らない注記（置き場所、形式、方針など）は、要るページのメッセージボックスで言う
- 一般の物（画面・マウス・人・建物・書類・暦など）の絵が `icons/` に無いときは、線の太さをそろえた SVG を作り（48×48 の枠、線の太さ 3.4、角は丸）、`sips -s format png -z 512 512 <svg> --out icons/<名前>.png` で PNG にする。色ごとに作る（文字の色、白、赤、強調の色。名前の末尾で分ける：`pic-people.png`・`pic-people-w.png`・`pic-people-r.png`・`pic-people-b.png`）
- 前面のメッセージボックスは、どの続きのページでも同じ位置に置き、指す先だけを変える。本文の下端（6.6）を越えない

## 外部の製品・会社のアイコン

### 線の絵をそろえる

- 線の絵（人・建物・書類など、1色のアイコン）は、`icons/` の1組から選ぶ。一覧は `icons/CATALOG.md`（名前と意味）と `icons/_catalog.png`（見た目）。名前に `pic-` が付くものも付かないものも、同じ線の太さの1組
- 色は、資料の色の組に合わせて塗り直す: `python3 <skills>/pptx-deck-design/scripts/tint_icons.py icons --ink <文字の色> --emph <強調の色> [--accent <問題の色>]`。元の絵は文字の色になり、色ちがい（`-w` 白・`-e` 強調の色・`-r` 問題の色）ができる
- 色ちがいは `d.icon(s, 名前, cx, cy, 大きさ, "w" | "e" | "r")` で選ぶ（色を塗った丸の上は `"w"`、対処や強調は `"e"`、問題は `"r"`）。`roadmap` の強調の駅は、自動で白になる
- 塗った色は `icons/.tint.json` に残り、資料の色の組と違うと、書き出しのときに警告が出る（塗り直す命令が、そのまま表示される）
- 公式のアイコン（Slack・Claude など）は塗り直さない

### 外部の製品・会社

- 図の要素として出す外部の製品・会社には、名前の横に公式のアイコンを置く。置き方: `compareTable` の列は `icon`、`processFlow` のセルは `{ icons: [...], text }`、`bizModel`・`archDiagram` の主体は `icon`、それ以外の部品は戻り値の座標を使って `d.icon(s, 名前, cx, cy, 大きさ)`
- `icons/` に無いアイコンは `python3 <skills>/pptx-deck-design/scripts/fetch_icon.py <名前> <公式の URL か手元のファイル> <作業フォルダ>/icons` で取得する。出どころが `icons/SOURCES.md` に残る
- 名前の見つけ方は `createDeck(pres, { brands: { 名前: /正規表現/ } })` で足せる。点検をやめるなら `brands: false`

## 吹き出し — `callout`

- 白箱に赤 1.25pt の枠と弱い影、赤の番号丸（`redDot`）、見出し bold＋起きたこと soft
- 引き出し線は図の空いた所を通し、文字に重ねない
- 見出しは前のページ（付箋など）と同じ言葉にする。並びは番号順

## 付箋ボード — `stickyBoard`

- ブレスト（洗い出し）にだけ使う。整理済みの能力や要件には使わない
- 帯（区分）を上から、帯の中のまとまりを左から。傾けない
- 選んだ付箋だけ不透明＋赤枠＋赤の番号丸、他は透過して灰字
- 付箋は見出しなしの1文。管理用の番号、AI が補った印は載せない。1件だけのまとまりを作らない

## 数値 — `barChart` / `waterfall` / `areaBars`

- `barChart`: 目盛り EEEEEE、文字 gray。棒の中に数値を入れない。強調（`highlight`）は内容で選ぶ:
  - 問題ではない主役（最新の年、最多の区分、展開した月）: `mode: "focus"`。その棒だけ濃紺で塗る。単系列なら系列の色は `C.bar`（灰）にしておく
  - 問題を示す棒: `mode: "frame"`（赤の太枠、色は元のまま）
  - 多数から選んだことが主張の盤面だけ: `mode: "fade"`（他を薄くする）。全要素を読ませる棒では使わない
  - 値を棒に添えるときは `values: { format, color, bold }`。棒の外の上に出し、縦軸と目盛り線は自動で消える。単系列（`grouping: "clustered"`）だけ
- 区分の名前・色・並び順は、棒・凡例・ガント・内訳で同じにする。凡例の一番下＝棒の一番下

### 図形で描く数値の図

ネイティブのグラフ（`barChart`）で描けない形は、次の部品で描く。build.js で矩形を並べて自作しない。

- `figHead(s, text, legend)`: 数値の図の左上に「何の数値か（単位・時点）」を 19pt soft で置く。位置は全ページ同じ（x 左マージン、y 本文の上端）。名前は図の中の、示すものの近くに書く。凡例（第3引数）は、図の中に名前を置けないとき（点の色・レーダーなど）だけ
- `colBars(s, { cats, series, focus, fmt })`: 縦棒。正負の値（0の線の下へ伸ばす）、1つの区分に2〜3系列の対の棒、棒の外の値を描く。系列の名前は、凡例の箱を置かず、最初の区分の棒の上に部品が書く。比べる2系列は主役を `main: true` にして濃紺、相手を `C.bar`。単系列で主役の1本だけ濃紺にし、その値を 36pt で棒の真上に描かせるときは `focus: [[系列, 区分]]`（対の棒でも、隣とぶつからない高さを部品が決める）。戻り値の `barX` / `barTop` で前面から指す位置を取る。対の棒の系列の名前は、部品が最後の区分の右に書く（`legend: false` で消す）。棒の太さと区分の幅は部品が決める。区分が少ないときは、間を広げず、棒と値をまとめて中央に置く。戻り値の `span(i, j)` は、i〜j の区分の棒・値・区分名（札の `from` に使う）
- `hBars(s, { rows, groups })`: 横棒。0の線から左右へ伸ばす。`x0`・`x1`・`bottom` で描く範囲を狭められる（前面の札の中など）。項目名が長い、正負が混ざる、全体と内訳を並べるときに使う。主役の行は `strong`（その値を 36pt で描かせるなら `focusValue: true`）。`null` の行で間を空けるのは、切り口が同じ区分の中だけ（全体と内訳など。`oneCut` にその切り口を書く。書かないと、確かめを促す警告）。世帯の区分と年代のように別の切り口は、混ぜずにページを分ける。連続した行のまとめ（「3つの団地で計 −3,376」）は `groups` で空いた側に1つだけ置く。行は本文の下端まで等しく広げる。行が少ない（2〜3行）ときは、行の間を広げず、棒を太くして上下の中央に置く。戻り値の `row(i, j)` は、i〜j 行目の矩形（札の `from` に使う）。項目名は軸のすぐ横に右揃え。名前の欄の幅・棒の太さ・間は部品が決める（`labelW`・`bh`・`pitch` は、別のページと図をそろえるときだけ。範囲の外は警告）。作法は [charts.md](charts.md) の「棒の作法」
- `ribbonBars(s, { cats, series, topLabel })`: 構成の推移。棒の高さは総量に比例、同じ区分を隣の期と帯でつなぐ。主役の区分は `main: true`（濃紺、名前を太字）。区分名は右端の棒の横に置き、凡例は置かない。棒の上の値（`topLabel`）は、リードが言う数値（割合など）にする
- 間隔の違う時点（5年刻みと直近年）を並べるときは、区分の名前に年を書き、等間隔で並べてよい。ただし時点の間隔が違うことが主張に関わる（増え方の速さを比べる）ときは、間隔をそろえた時点だけを使う
- 数の書式は `fmtNum(v, { plus, digits, unit })`（負は全角のマイナス「−」、正負が混ざる図では正に「+」）
- `waterfall`: 期ごとの増分は灰の棒＋「+値」、右端の累計の棒だけ区分色で積む
- `areaBars`: 横幅＝期間、高さ＝月額。費用と期間を同時に見せるときに使う。総額の積み上げにしない
- 推移の線は、線・点・目標線を1つの描画関数にして全ページで共有する（自社＝濃紺実線と塗りの点、他社＝灰の線と白抜きの点、見込み＝点線、目標＝太い破線と真上のラベル）

## 構造の図

引数の詳細は各関数の先頭のコメント、使い方は `assets/sample-flow.js`・`sample-map.js`・`sample-diagrams.js`。どれも戻り値に、重ね技（`echo` の `keep`）で前面から指すための座標を返し、`only` で指す要素だけを元の濃さで描き直せる。共通の基準: 戦略コンサルはスカスカの図を使わない。本文の領域（y 2.2〜6.6）を使い切る密度と詳しさにする。言葉の意味を図の形で表す（ループは円）。

- `processFlow`: 工程の流れ。上に工程の矢羽、下に所要（作業と待ちの積み上げ棒）と、短い札の行を2行まで（全角12字まで・1行。超えると警告）。工程ごとの説明は、続きのページのメッセージボックスで言う。詰まる工程は列全体を赤枠で囲む
- `swimlane`: 詳細なスイムレーン。5〜6レーン×10前後の工程、段階の矢羽、判断のひし形、帳票、システムの円柱、列ごとの所要。線は鉤に折り、差し戻しは赤。交差と重なりは警告で知らせる。工程の名前は短くする（10列近いと1行は全角4字ほど、2行まで）
- `cycleDiagram`: 繰り返し・周期。ドーナツを3〜6区画に分け、先端の矢じりで時計回りを示す。名前と説明は環の外に水平な引出線で、中心に回すもの・回数・主張。下に別のメッセージ欄は作らない
- `orgChart`: 体制。責任者 → 部署 → チーム（リーダー）→ メンバーの樹形。直属の事務局、人数、兼務、社外（破線）を表せる。主導の部署だけ濃い塗り＋紺の枠
- `matrix2x2`: ポジショニング（軸の両端の意味、バブルの大きさ＝第3の量、空白地帯、右に読み取りの要点）と2×2（象限ごとに名前・方針・項目、狙う象限を1つ強調）。名前は重ならない位置を自動で選ぶ
- `funnel`: 中心をそろえた台形の段を一定の比率で狭める（値に比例させると形がいびつになるため、値は数字で示す）。右に数と次へ進む率、その右に段ごとの説明の列。落ちる所だけ赤枠
- `archDiagram`: アイコンを使った構成図。格子（cols・rows）の上にノード（アイコン＋名前＋小さい説明）、まとまり（塗りの領域か破線の境界）、鉤の矢印とラベル。示唆は `notes` で前面に番号つきの箱。アイコンは `icon(s, 名前, cx, cy, d)`／`iconPath(名前)` で、`assets/icons/` から読む（ブランドは実物の色、汎用は ink）
- `eventTimeline`: 年月の軸に出来事の点。名前は点の真下、近いものは段をずらして細い引出線。自社だけ濃紺・太字
- `stateMap`: 区分の枠に項目の箱を並べ、状態を枠・破線・文字の濃さで描き分ける
- `decisionPage`: 決裁の依頼。番号・決める内容・選択肢（推奨の1つに濃い塗り＋枠＋「推奨」）・根拠（P.n）・決めた後を、左から1行で読ませる

## 数値のグラフ

王道のグラフ33種の選び方と部品は `references/charts.md`。共通の規律:
- 主役の系列・区分だけ濃紺、他は灰か区分色。名前は線・区分の横に直接書き、凡例に頼らない（レーダーだけ例外）
- 目盛り線は使わず、値は図の中に直接書く。目標・平均は `refLine`（破線。目標でも赤にしない）
- 積み上げ（縦・横・100%・マリメッコ・ツリーマップ）は、区分の値を区分の中に書いてよい（高さが足りない区分は省く）。それ以外の棒は値を棒の外に
- 円・ドーナツは区分5つまで、大きい順、主役の区分だけ濃紺。時系列には使わない
- 2軸の複合グラフにしない（`comboChart` は上下2段に分ける）
- 桁の違う系列の伸びを比べるときは `lineChart` の `log: true`（底10。`min` は必須で 0 より大きい値）。figHead に「対数軸（傾きが年平均成長率を示す）」と書き、系列の `cagr` で右端に年平均成長率を出す。増減の棒の値の書式を変えるなら `bridge` の `stepFmt`

## 市場の絞り込み — `tamSamSom`

- 市場規模（TAM・SAM・SOM）を1つの図で見せる。左に下端で接する入れ子の円、右に同じ高さの行を3段（`compareTable` と同じく、行の間は薄い細線。背景色は狙う1行だけ）
- 大きさは金額に比例しない（桁が違いすぎて比例では読めない）。金額は行の数字で読ませる
- TAM・SAM・SOM それぞれが何の市場かを、一言で書く（`what`。全角12字まで）。円の中に出る。略語と金額だけにしない
- 列の見出しは `heads` で替えられる（既定は「区分と金額」「対象」「算定の根拠」）
- 1金額ごとに対象（`scope`）と根拠（`basis`）を対で書く。根拠は「何×何」と式で書ける形にする
- 実在の資料の仮値は、金額の文字に（仮）を付ける（「約27億円（仮）」）。下の小さな文字（`sub`）に逃がさない。架空の題材・見本、依頼者が札を外すと決めた資料では付けない
- 強調は狙う1行だけ（`strong`）。帯を濃くして ink 2pt の枠、金額をさらに大きくする
- 本文の上端から使うので `figHead` と併せない。何の市場かは `what`、時点はリードに書く（`figHead` を置くなら `y0: 2.55`）
- 幅は `circleW`（円の直径）と `colW`（`[区分と金額, 対象, 算定の根拠]`）で調整する。戻り値の `row(i)`／`circle(i)` で前面から指す位置を取る

## コンセプト — `concept`（2026-11-25）

- 新しい事業・製品・サービスを初めて見せるページ。属性（誰に・何を・いくらで）を並べず、価値を一目で見せる（決まり25）
- 作る前に「このページで一番伝えたいこと」と「見た人に分かってもらえれば OK なこと」を1文ずつ決める
- 価値を言う一文（`statement`、全角30字まで）を中央に。1語だけ強調の色（`key`）。説明の小さな文（名前の札 `name`・物差しの説明 `note`・帯の端の札 `end`）は置かない（渡すと警告し、描かない）
- 一点突破：伝える価値は1つ、物差しは1本、比べる相手は1つ。一文はマジックワード（短い言い切り）にする（16字までなら大きく出る）
- 価値の差が1つの物差しで言えるなら `contrast`：比べる相手1つと自社の2行を同じ物差しに並べ、自社の行（`strong`）だけ強調の色。自社の帯の横に大きく一語（`big`）。右端の結果の値（`result`）や3行目は足さない（警告）
- 帯の長さと目盛りの位置は、割合で決めずに値で渡す：`rows` の `value`、`ticks` の `value`（左端と右端は `min`（既定 0）・`max`（既定は最大の値））。長さは部品が計算する。前の書き方の `to`・`at` は警告
- `value` に入れてよいのは、原稿にある値（調査・計算で足したなら、台帳に出どころがある値）だけ。値の無い行と、範囲しか分からない行（`value` か `big` が「未満・以上・以下・以内・〜」）は、帯を描かずに警告する
- 物差しで言えないなら、`contrast` を渡さない（一文だけを中央に、2行まで）。比べる相手の値が分からないときも、これ
- `contrast`（同じ物差しの帯）は、価値を見せる形の一例にすぎない。題材によって、線（差が時間とともに開く）、アイソメトリックの図解や流れ（手間・工程が減る）、俯瞰の図（場所・規模）、写真や画面（見た目そのものが価値）のほうが伝わる。逆算して形を選び、部品に無い形は決まり6のとおり描いてよい（SKILL.md 決まり25）
- 要点の列（`points`）は使わない（警告）。初見の聞き手（`audience: "first-time"`）には、仕組みの図の前に置く

```js
const s = d.base("サービスのコンセプト", null, { focus: "やさい一皿の「当日」" });
// 伝えたいこと：収穫から冷凍までが圧倒的に短い／分かればOK：やさい一皿は、とれたその日に冷凍している
d.concept(s, {
  statement: "畑から冷凍まで、当日。",
  key: "当日",
  contrast: {
    ticks: [{ value: 0, label: "収穫" }, { value: 1, label: "1日" }, { value: 2, label: "2日" }, { value: 3, label: "3日" }],
    rows: [
      { name: "他社の冷凍のおかず", value: 3 },
      { name: "やさい一皿", value: 0, big: "当日に冷凍", strong: true }, // 当日＝0日後（帯は最小の幅）
    ],
  },
});
```

## 要約 — `summary`（2026-11-25）

- 要約のページは、これで描く。`points`（見出しと補足の文の羅列）で描かない（要約のページで `points` を呼ぶと警告）
- 上に「決めていただくこと」を1つ（`decision`: `text` と `value`。値は主役の値 36pt・強調の色。ページの見る所はこの値）。下に根拠を 2〜4 個並べ、上の箱から直角に折れる線でつなぐ（ピラミッド）
- 根拠は「見出し1つ（`head`、全角24字・2行まで、20pt bold）＋値1つ（`value` 28pt bold、横に短い語 `unit` 16pt）」だけ。補足の文（`body`）は付けない（付けると警告）。根拠のページは `refKey` で「根拠 P.n」
- 何をどう読むかは、上から下へ「何を決めるか → なぜか」。根拠の順は、その資料で話す順

```js
const s = d.base("要約", "「野菜の多い1皿を450円で」なら、後発でも勝機。", { focus: "予算 1,200万円" });
d.summary(s, {
  decision: { text: "試作と試験販売の予算", value: "1,200万円" },
  reasons: [
    { head: "買う人の不満の1位は「野菜が少ない」", value: "58%", unit: "共働きの世帯", refKey: "fuman" },
    { head: "野菜の多い商品は、ほとんど無い", value: "8品", unit: "120品目のうち", refKey: "tana" },
    { head: "約450円なら払ってもらえる", value: "450円", unit: "368円＋80円", refKey: "harau" },
  ],
});
```

## 要点と説明の2段 — `points`

- 示唆・提言・申し送りのように、1項目に「言い切りの要点」と「根拠の1文」があるときに使う。事実だけの列挙は `bullets`
- 要点 22pt bold ink、説明 20pt soft。黒丸は付けない
- 根拠のページがあるなら `refKey` で右端に「根拠 P.n」
- 項目の間隔は本文の下端までを等分する（最大 1.25in）

## 箇条書き — `bullets`

- 事実の列挙、活動報告、総括、知見は図にせず、これで1列に書く
- 項目は文字列、区分があるときは `{ head, items }`（小見出し 22pt bold＋箇条書き 20pt）。区分は構成案にあるものだけ使い、分類ラベルを自分で足さない
- 順に意味があるときだけ `numbered: true`
- 項目が少なく下が空くのは許容する。文字を上げて埋めず、必要なら `gap` で項目の間を広げる

## 骨格 — `base` / `cover` / `chapter` / `divider` / `agenda`

- `base(title, lead, o)`: 全ページの土台。タイトルは、そのページの図とリードが扱う中身の名前（普通に使う言葉で、何のことか分かる名前。SKILL.md の7。`null` にすると、いまの章の項目名になる。使うのは中身が章の全体と合うページだけ。題の中心の言葉が図の見出し・札の見出し・リード・図の文字のどこにも無いと警告）、リードは結論1つを言い切る（2行・70字まで。「だ」「である」で結ばず、文末は体言止め（名詞で止めると不自然な依頼などは、動詞のまま可）。タイトルで分かることは書かない。決まりは SKILL.md の11）。`o.ask` に、聴講者が持ちうる疑問と答えの場所を書く（`"どの工程？ → リードの「購買部の確認」"`。文字か配列。画面には出ない。`series` のページは `ask`。リードがあって空だと警告）。`finalize` は、見る所の一覧 `<資料名>.focus.md` と、題・図の見出し（札の見出し）・リードを横に並べた一覧 `<資料名>.leads.md` を書き出す（`createDeck` の `focusList: false`・`leadList: false` で止める）。`o.focus` に見る所を1つ書く（列挙だけのページは `false`）
- 色: `createDeck` の `theme` で決める。名前（`blue`・`teal`・`green`・`orange`・`purple`・`slate`・`navy`）、強調の色だけ（`{ emph: "2F6BFF" }`）、全部の指定、のどれでも渡せる（`references/tokens.md` の「色の組を差し替える」）。決めないと警告が出る
- 題の形: 中身の名前の題＋リードだけ。報告書でも、題に結論の1文を書かない（`titleStyle: "action"` は、指定すると警告が出る）
- フッター: `createDeck` の `footer`。`"page"` は、細い線の下の左に `footerText`（資料名）、右にページ番号（`footerText` を省くとページ番号だけ）。表紙と区切りのページは、ページ番号だけ。`"band"` は下に濃紺の帯（左に `copyright`、中央にページ番号、右に `logo`）
- `cover`: 既定はタイトルと日付だけ。経営会議用の報告書だけ `kicker`・`sub`・`affil` を足す
- テーマ（会社・個人の見た目）: `createDeck` の `theme` に既成のテーマの名前（`standard`・`corporate`・`pitch`）か JSON のパスを渡すか、プロジェクトの `.claude/pptx-deck/theme.json`・個人の `~/.claude/pptx-deck/theme.json` に置く（`SKILL.md` の「テーマ」）。項目は `references/tokens.md` の「テーマの設定の項目」。`createDeck` の opts の `font`・`sizes`・`layout`・`cover`・`pageNumber`・`confidential`・`footer`・`footerText`・`copyright`・`logo` は、テーマより優先する。読み込んだ結果は `d.theme` で見られる
- テーマの `cover` は、表紙の型（`style`）、所属の既定（`affil`）、ロゴ（`logo`・`logoPos`）を決める。`cover(o)` の `affil` を書けば、そちらが勝つ
- テーマの `footer` は、帯かページ番号だけか、ページ番号の有無、資料名、著作権の表記、ロゴ、「社外秘」などの表記を決める
- `chapter`: 番号と章題だけ。説明や副題を書かない
- `divider`: 紺地の区切り。濃紺の全面塗りはここだけ
- `agendaPage(o)`: アジェンダ。8 枚以上の資料は、表紙（と要約）の後に必ず置く（置かないと書き出しのときに警告。2026-11-25）。枚数の指定は、表紙とアジェンダを数えない本編の数として扱う。`createDeck` の `nav` に書いた章の項目名を、話す順に縦に並べる。主張や数字は書かない。章は `d.setChapter(番号)` で切り替える（その章の最初のページの番号が、アジェンダに出る）。`active` で今の章だけ濃くできる
- `agenda`: 章と節を2列で載せる目次（報告書向け）。章（大項目）だけ。2列にするときは右（参考）を一段弱く。ページ番号は `finalize` が描く
- ミニ目次（右上の現在地）: 既定では出さない。`createDeck` の `nav`（章立て）に加えて `miniNav: true` を渡すと出る。章のない資料や動画上映が中心の資料では付けない
- `source`: 既定では使わない。詳細へ飛ばしたい数値だけ1行のリンク
- 他のページの参照（P.n）は `mark` と `ref` で後から自動で入れる

## 小部品

- `arrowR`: 塗りの右矢印（既定 gray）。文字の「→」を図の中に混ぜない
- `PT`: 手順図の小三角
- `numDot`（紺）／`redDot`（赤）: 番号を付けたもの自体がその場にあるときだけ。離れた場所の説明と番号で対応づけない
- `person`: 人のピクト。体制は同じアイコンを人数分、色は統一

## 見る所の値（focusValue）

- `d.focusValue(s, text, { x, y, w, h?, align? }, { problem? })`：グラフの見る所の値を 36pt・太字・強調の色（problem なら赤）で書く。見る所のすぐ隣に置く（決まり23）
- 部品が自分で描く見る所の値（`colBars` の `focus`、`metricBars` の `key`、下の「主役の値を部品で描く口」）も同じ大きさと色になる。`lineChart` の `main`・`smallMultiples` の `strong` の線は 3pt・強調の色、他の線は 1.25pt
- `matrix2x2` の点の `self` は強調の色。`projectGantt` の作業の `focus: true` は強調の色で、他の帯は灰になる
- グラフの部品を使ったページで、見る所の大きな値（24pt 以上・強調の色か赤）が無い／2つ以上だと警告が出る。見る所の無いページは `focus: false` を宣言する

## 決裁のページ（2026-11-24。2026-11-25 に改めた）

- 主役の図は、決める額の内訳（費目ごとの `hBars` か `compareTable`）と、決めた後の次の一歩（いつ・誰が・何を。`eventTimeline` か `bullets`）。計画の図（`roadmap`）を主役にしない（決裁のページが計画のページに見える）
- 決める額は `focusValue` で 36pt・強調の色。合計の棒の先か、内訳の見出しのすぐ横に置く
- 根拠の計画の図をもう一度見せたいときは、`series`・`echo` で背面に敷いてよい（同じ図を敷く手法は、決まり2のまま）。ただし前面の箱で、背面の図の段階や文字を隠さない。箱は空きに置く
- 内訳と次の一歩を、箱の中の小さな文やノートに回さない
- 1ページで決めてもらうのは1件。2件以上なら、ページを分ける。`decisionPage`（文のマス目）は使わない

## 主役の値を部品で描く口（2026-11-24）

主役の値を、呼ぶ側で値を空にして `focusValue` で手で置くと、部品が隣の棒・値の位置を知らないので重なる（対の棒の「240」が隣の棒に重なった）。口のある部品では、主役の要素に印を付け、部品に 36pt の値を普通の位置へ描かせる。部品は隣とぶつかるならよけ、よけきれないときは警告を出す。

| 部品 | 口 | 描く位置 |
|---|---|---|
| `colBars` | `focus: [[系列, 区分]]` | 棒の真上（負は真下）。対の棒で隣の棒・値に重なるなら、隣の値より上へ上げる（上の余白が足りなければ、`max` を渡していないとき部品が広げる） |
| `hBars` | 行に `focusValue: true` | 棒の先。値の列はその幅だけ広がる |
| `lineChart` | `focusValue: [系列, 点]`（`focusBelow`・`focusProblem`） | 点の上（下）。最後の点なら右端の名前から値を外す |
| `slopeChart` | 行に `focusValue: true` | 右端の値（点の右、名前の前）。ほかの行の名前はその高さだけよける |
| `bridge` | 要因に `focusValue: true`（`start`・`end` にも付けられる） | 増は棒の上、減は棒の下。強調の色の塗り（`focus`）も兼ねる。`problem` と一緒なら赤 |
| `waterfall` | `steps`・`total.parts` の1つ、または `total` に `focusValue: true` | 増分は棒の上、内訳は右のラベル（区分を強調の色で塗る）、累計は棒の上 |
| `heatmap` | `focusValue: [行, 列]`（`focusProblem`） | セルの中。濃いセルは白。36pt がセルより広いと警告 |
| `tamSamSom` | 行に `strong: true` | 金額を 36pt・強調の色で（金額を空にした古い呼び方は、今まで通り 22pt） |

```js
d.hBars(s, { fmt: v => v.toFixed(1), rows: [{ label: "駅前店", value: 6.8, focusValue: true }, { label: "本店", value: 6.1 }] });
d.lineChart(s, { cats, series: [{ name: "会員数", values, main: true }], focusValue: [0, 11] });
```

- 主役の値は1ページに1つ。口のある部品で、値を空にして `focusValue` を手で重ねない（大きな値が2つになり警告が出る）
- 手で `focusValue` を置くのは、口の無い部品（`pieChart`・`stackBars`・`mekko`・`treemap`・`ribbonBars`・`areaChart` など）だけ

## 見る所の値と、部品の値が二重になるとき（口の無い部品）

- 口の無い部品で `focusValue` を手で大きく書くときは、部品の書式の関数（`fmt`・`pctFmt` など）で、その値だけ空の文字にする（例：`fmt: v => (v === 主役の値 ? "" : f1(v))`）

## 推計の幅（range）・市場の円・ファネル（2026-11-24）

- 年平均成長率：`colBars` の `cagr: { from, to, years?, label? }`。最初と最後の棒を矢印でつなぎ、「年平均 +x%（期間）」を値から計算して書く。市場の大きさ・成長には対数軸を使わない
- `lineChart` の `range`（推計の幅の帯）は、市場の推計には使わない。折れ線は3本まで（4本以上は警告）
- `tamSamSom`：円の中に、区分名（TAM など）と何の市場かの一言（`what`）を書く。その円に実際に入る字数（外 9字・中 7字・内 5字ほど）を超えると警告。右の行は区分名・金額・対象・根拠。`strong` の行の金額は 36pt なので、金額の列（`colW[0]`）をその幅に合わせる
- `funnel`：件数は段の中に、段名と一緒に書く（段名の下に件数）。率の列は1つだけ。既定は「次へ進む率」（どこで落ちるか）。`rate: "fromTop"` で「最初からの率」に入れ替える（このとき落ちる所の印 `drop` は使えない）

## 流れ図の見た目（2026-11-24）

前の版は、薄い矢羽の下にマス目を積み、スイムレーンは薄い帯の上に白い箱と細い線を並べていた。どれも同じ明るさで強弱が無く、表に見えるかぼやけて見えた。

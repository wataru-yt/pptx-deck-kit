# 王道のグラフの一覧（数値の図）

戦略コンサル・ビジネス資料で使う王道のグラフと、`deck-parts.js` の部品の対応。見本は `sample-charts.js`（1種類1ページ、P は見本のページ。2026-11-24 に、スモールマルチプルと KPI タイルを外して32ページにした）。

共通の規律: 見る所の系列・区分だけ強調の色、他は灰（決まり23）。見る所の値は 36pt で、その要素の普通の値の位置に書く。濃紺の本数はリードが名指しした数と同じ。目盛り線は引かず、値と名前は図の中に直接書く（凡例の代わり）。罫線の表のような格子は使わない。何の数値か・単位・時点は `figHead` で左上に。強調は1ページ1種類。赤は問題だけ（目標線も赤にしない）。

## 棒の作法（必ず守る）

棒を使う図は、次の形で描く。太さ・間・名前の欄の幅は部品が決めるので、build.js で指定しない。図は読みやすい密度で描き、余白は残してよい（本文の領域を埋めるために、棒を太くしたり間を広げたりしない）。

| 作法 | 内容と目安 | 部品の既定・警告 | 根拠 |
|---|---|---|---|
| 間は棒より狭い | 棒と棒の間は、棒（群）の幅より狭く、細すぎない。目安は太さの 25〜60% | 横棒の間は太さの半分ほど。4分の1より狭い・太さより広い指定は警告。縦棒は区分が少ないと図を狭めて中央に置く | GOV-1・GOV-2・STW |
| 太すぎない | 太い棒は、図が塗りの塊に見え、値が読みにくい | 横棒の太さは本文の文字の高さの 1.15〜1.6 倍、縦棒は1本 1.0 インチまで。超える指定は警告 | STW（決まった比はない。この数値はこのスキルの基準） |
| 群の間は、群の中より広く | 対の棒は、同じ区分の棒を寄せ、区分の間を空ける。系列は2つが読みやすく、多くても3つ | `colBars` が決める | GOV-1 |
| 名前は軸のすぐ横 | 横に伸びる棒の項目名は、右にそろえて棒の起点の直前に置く | 横棒・横の積み上げ・ブレット・指標ごとの棒・ガントの作業名 | このスキルの基準（名前と棒の間の空きをなくす） |
| 名前は横書き。長い名前は横棒 | 名前を斜めや縦にしない | 入らないと警告 | GOV-1 |
| 凡例より、図の中に直接 | 系列・区分の名前は、棒のそばに書く | 対の棒は最後の区分の右（軸の近く）。積み上げは右端の棒の横か一番上の棒の上。見出しの行の凡例は、対の棒で警告 | GOV-1 |
| 0 から始める | 棒の長さが値なので、軸を途中から始めない・省かない | 縦棒・横棒は 0 から | GOV-1・GOV-2 |
| 値は棒の端の外 | 値は棒の端のすぐ外。値を書いたら、軸の目盛りと目盛り線は消す | 部品の既定 | GOV-2・EUR |
| 並べ順 | 順序のある区分（年・年代）はその順。順序がなければ値の大きい順 | 並びは build.js で決める | GOV-1 |
| 色は意味があるときだけ | 1系列は1色。見る所の1つだけ強調の色 | 決まり23 | GOV-2 |
| 飾らない | 3D・影・模様を使わない | 部品の既定 | GOV-2 |

出典（2026-11-27 に確認）:

- GOV-1: UK Government Analysis Function, Data visualisation: charts https://analysisfunction.civilservice.gov.uk/policy-store/data-visualisation-charts/
- GOV-2: 同, Introduction to data visualisation, Module 5: bar charts https://analysisfunction.civilservice.gov.uk/support/communicating-analysis/introduction-to-data-visualisation-e-learning/module-5-bar-charts/
- EUR: data.europa.eu, Data visualisation guide: bar label placement https://data.europa.eu/apps/data-visualisation-guide/bar-label-placement
- STW: storytelling with data, adjusting bar width（厳密な決まりはなく、空きが目立たない太さにする） https://www.storytellingwithdata.com/blog/2021/9/8/how-to-do-it-in-excel-adjusting-bar-width

## ネイティブか図形か

pptxgenjs のネイティブのグラフ（pie・doughnut・line・area・scatter・bubble・radar・bar）は、次の点でこの規律を満たせない。

- 系列・区分の名前が凡例になる（線や区分の横に直接書けない）
- 値のラベルの位置と書式を PowerPoint が決める。主役の1点だけ太字・大きくできない
- 1点だけの色・強調は、書き出し後に XML の dPt を足さないと入らない（`barChart` の `highlight` はこれをしている）
- 目標線・見込みの点線・平均の破線・象限の名前・ドーナツの中央の合計を重ねる位置が、グラフの中の描画領域に依存して定まらない

そこで、ネイティブは既存の `barChart`（縦棒・積み上げ）だけに残す。使うのは、期が多い（13期以上）・PowerPoint 上で他の人が値を差し替える資料に限る。それ以外は図形で描く部品を使う。

## 使わないグラフ

| グラフ | 理由と代わり |
|---|---|
| 3D のグラフ、影・光沢のある棒 | 奥行きで値が読めなくなる。平面で描く |
| 2つの縦軸の複合グラフ | どちらの軸で読むか迷い、線と棒の交わりに意味が見えてしまう。`comboChart`（段を分ける） |
| 年ごとに並べた円、2つの円の比較 | 角度の差は読めない。`stackBars({ pct })` か `ribbonBars` |
| 6区分以上の円 | 小さい区分が読めない。`hBars` か `treemap` |
| ゲージ・メーター | 面積の割に情報が少ない。`bulletChart` |
| 線の多い折れ線（4本以上） | 線が絡む。リードに効く系列だけ残し、3本までにする（4本以上は警告） |
| 凡例だけで区分を示す図 | 視線が往復する。区分名を図の中に直接書く |

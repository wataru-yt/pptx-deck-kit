# 論旨から必要な情報を組み立てる

資料は、伝える論旨に必要な情報を組み立ててから図にする。手元の原稿にある数値から図を決めない。原稿は材料であって、情報の上限ではない。市場規模のページで原稿の数値だけを使い、調査会社の推計の開きを描いて、TAM・SAM・SOM と年平均成長率を選べなかった失敗から。

## 順序

1. **資料の論旨を1文で書く。** 誰が何を判断するための資料か。
2. **ページごとに「読み手の問い」と「伝えたい1文」を書く。** 問いは読み手の言葉で（「どれだけ大きく、どこまで取れるか」）。タイトルとリードだけを順に読んで論旨が通るようにする。
3. **問いに答えるのに必要な情報を書き出す。** 下の「論点の型」を使う。この時点では、手元にあるかどうかを見ない。
4. **手元の原稿と照合し、台帳を作る。** 足りない情報が調査の対象になる。
5. **足りないものを自分で調べる。** 公開統計、調査会社の公表値、各社の発表、価格表、社内の資料。定義と年をそろえ、互いに矛盾する値は両方残す。
6. **調べても分からない値は仮値で埋める。** 欄を空けない。分からないからといって、図の形式を下げない。
7. **形式を選ぶ（`form-selection.md`）。** 論点の型が求める図を第一候補にする。
8. **描いて点検し、最後の返答で調査を依頼する。**

## 原稿の扱い

| 内容 | 扱い |
|---|---|
| 主張、論点の順序 | 原稿に従う。変えたいときは提案し、了承の後で行う |
| 主張を支える数値、比較の対象、根拠 | 足りなければ了承なしに足す |
| 原稿の主張と、読み手の問いがずれている | ページは問いに答える形で作り、原稿の主張は注釈や別ページで残す。ずれは最後の返答で知らせる |
| 調べた結果、原稿の数値や主張が古い・誤り | 勝手に直さず、両方を示して最後の返答で確認する |

## 論点の型ごとの必要情報

型に当てはまる論点では、ここに挙げた情報を一通りそろえる。合わない項目は外してよいが、手元に無いという理由では外さない。

| 論点 | 読み手の問い | 必要な情報 | 図の第一候補 |
|---|---|---|---|
| 市場規模 | どれだけ大きく、どこまで取れるか | TAM・SAM・SOM それぞれの金額、対象、算定の根拠、年 | `tamSamSom` |
| 市場の成長 | 伸びるのか、どれくらい確かか | 実績の推移、将来の見通し、年平均成長率（CAGR）、調査ごとの定義の違い | `lineChart`（桁が違えば `log`、右端に `cagr`） |
| 競合 | 誰がどこを押さえ、空白はどこか | シェア、製品の範囲、価格、参入の時期、位置づけの軸 | `matrix2x2`、`compareTable`、`eventTimeline` |
| 顧客・用途 | 誰が、なぜ今買うか | 対象の企業数、課題の頻度と大きさ、今の代替手段、支払う理由 | `compareTable`、`funnel` |
| 経済性 | 投資を回収できるか | 単価、獲得の費用、粗利、固定費、回収期間、損益分岐、感度 | `bridge`、`lineChart`、`compareTable` |
| 施策の効果 | 費用に見合うか | 効果の量、費用、前提、感度、今のやり方との差 | `bridge`、`matrix2x2` |
| 原因 | なぜ起きたか、どこを直すか | 発生の件数と内訳、因果の根拠 | `logicTree` |
| 検証の計画 | 何が分かれば次へ進むか | 仮説、指標、合格の基準、期間、費用、次の判断 | `projectGantt`、`roadmap` |

## 仮値の書き方

- 実在の資料では、図の値に直接「（仮）」を付ける（架空の題材・見本の値、例として置いた社内の決まりの値は、仮値に当たらない。依頼者が札を外すと決めた資料では付けず、台帳に残す）。結論が仮値に依存するときは、タイトルとリードの数字にも付ける。
- 文字の色は他の値と同じにする（gray や pale で薄くしない）。線なら点線、棒なら灰。
- ページの下に「※」の注記を作らない。前提は台帳に持ち、効く前提だけ図の該当箇所に短く書く。
- 分かっている値から積み上げて作る（企業数 × 導入率 × 単価）。勘の1点で置かない。振れ幅が大きければレンジで書く。
- 仮値を置いたら、必ず調査依頼を出す。

## 数値を文に書く前の確認

2026-11-09 の別担当の検証で見つかった誤りから。

- タイトル・リード・対象欄の条件は、算定の式に入っているものだけを書く（式に無い「手戻りが多い企業」を対象に書かない）。
- 金額の種類を書く。累計か年間か、実績の売上か、全社導入を仮定した潜在額か。
- 基準の違う数字を入れ子で並べるときは、実績の市場と比べる値を隣に置く。
- 年平均成長率には期間を添える。起点の年が変わると値が変わるので、見出しの主張がどの起点で成り立つかを確かめる。
- 線の傾きとラベルの年率が合わないときは「傾きが年率を示す」と書かない。
- 別の母集団の調査を代用した値は、母集団と偏りを台帳に書き、出典名は実際の調査主体にする。
- 仮値を掛けて出した幅にも（仮）を付ける。
- 前提を変えたら、台帳の派生値を全ページで洗い直す（前の前提の「20拠点」が残るなど）。
- 「各社とも」「8社とも」と書くときは、表の中の数と確認の深さに合わせる。
- 別の調査や手法に出した比較の数値を、基準の根拠のように並べない。

## 台帳

`build.js` の隣に `data-ledger.md` を作る。ページに置く数値はすべて載せる。

| 列 | 内容 |
|---|---|
| ID | build.js と対応する名前 |
| 値・単位・年 | 例: 約11億ドル、2024年 |
| 定義 | 何を含むか（ソフトのみか、サービス込みか） |
| 状態 | 原稿／調査／計算／仮値 |
| 出どころ | 調査名と URL。計算は式。仮値は前提 |
| 確認の深さ | 本文を読んだ／抄録／検索の抜粋のみ |
| 使うページ | P.n |

追加調査で外から持ち込んだ数値のページには、`source` で1行の出典（調査名と年）を置く。URL は台帳に持つ。

## 調査依頼（最後の返答に必ず書く）

仮値が1つでもあれば、最後の返答で調査を依頼する。自分で調べて見つからなかった値と、依頼者にしか分からない値（自社の単価、社内の実績）が対象。

| 優先 | 確かめる数値（今の仮値） | 必要な理由・結論への影響 | 当たる先（資料名、部署、質問の文） | 差し替える場所 |
|---|---|---|---|---|

- 結論に効く順に並べる。
- 当たる先は、そのまま動ける具体さで書く（「ITR に問い合わせる」ではなく、レポート名と知りたい数字）。
- 試して見つからなかった調査を1行添える。
- 回答が来たら、台帳 → `build.js` の順に差し替える。結論が変わるならタイトルとリードも直す。

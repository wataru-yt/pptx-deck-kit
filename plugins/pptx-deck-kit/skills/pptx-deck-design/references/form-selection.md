# 内容の種類と見せ方

ページの「読み手の問い」と「伝えたい1文」、必要な情報を決めてから（`argument-and-evidence.md`）、形式を選ぶ。部品の組み方は `components.md`、関数は `assets/deck-parts.js`。

## 先に：持ち帰る1つ（2026-11-27）

1. このページで読み手が持ち帰る1つ（語か数値）を書く。
2. それを支える情報を書く。
3. 持ち帰る1つがいちばん大きく見える形を選ぶ。下の表は**候補の例**で、決まりではない。手元の中身の形（列挙・段階・表）から機械的に選ばない。
4. 合う部品が無ければ、基本の図形（文字・四角・線）で描いてよい。持ち帰る1つを大きく置き、支える情報を隣に置く。1ページ1メッセージ、見る所1つ、読める大きさは守る。

手元の数値で描けるかどうかで形式を決めない。表の「却下された形式」の列にあるものは使わない。

## 動詞から候補を挙げる（2026-11-24）

形式の候補は、伝えたい1文の動詞から挙げる。原稿の書き方（2つを対比している、番号が付いている）で決めない。同じ資料の中で、1つの形は1つの意味にだけ使う。

| 伝えたい1文の動詞 | 形 | 部品 |
|---|---|---|
| 満たすかどうかで比べる（機能・条件の有無） | 評価の丸・星の表（5行×4列まで。セルに文字を入れない） | `compareTable` |
| 同じ単位・同じ桁の数値を見比べる | 小さな数値の表 | `compareTable` |
| 単位や桁の違う数値で、いくつかの対象を比べる | 指標ごとに尺度をそろえた棒 | `metricBars` |
| どこで起きるか・どの時点かの違いを言う | 1本の道（時間や工程）の上に、位置を置く図 | 自作の図 |
| 前と後の違い（いまのやり方とこれから） | Before / After の2列。左右に同じ段を同じ位置で並べ、違う段だけ強調（無い段は破線の空き枠） | 自作の図（位置を道に置く等。読み方が分からない） |
| 違いを言う（前と後、自社と他社の1点の差） | 決め手の数値を大きく、または前後を並べた図・棒 | `colBars`・`hBars`・自作の図 |
| 順に進む | 流れ | `processFlow` |
| 受け渡す・中継する | スイムレーン | `swimlane` |
| 回る・繰り返す | 循環 | `cycleDiagram` |
| 誰が、誰に、何を渡す（お金がどこで入るか） | ビジネスモデル図 | `bizModel` |
| 分かれる・原因をたどる | 樹形図 | `logicTree` |
| 指標を分解する（掛け算・足し算でつながる） | KPIツリー | `kpiTree` |
| 誰が実行し、誰が決めるか | RACI | `raciTable` |
| 絞り込む | 入れ子の円・ファネル | `tamSamSom`・`funnel` |
| 位置づける | 2軸 | `matrix2x2` |
| いつ・どの段階で | 段階の道・ガント | `roadmap`・`projectGantt` |
| 増える・減る・推移する | グラフ | `references/charts.md` |
| 並べて挙げる | 箇条書き | `bullets`・`points` |
| 全体の仕組みを俯瞰する（何が、どこへ集まり、何になるか） | 中身に合わせたインフォグラフィック | 部品に合う形が無ければ、build.js に図を描く関数を1つ書く（`references/components.md` の「自作の図」） |

資料の中で同じ動詞のページが2つあり、中身が別の話なら、どちらかの言いたいことを見直す（課題＝「受け渡す」、解決策＝「順に進む」のように、動詞が違うはず）。

## 表・図・文章・箇条書きの選び分け

| 内容 | 選ぶもの |
|---|---|
| 比較 | 数値・評価の丸の表（`compareTable`）。文で書く根拠の対応やルールと例外は、表にせず `points` か図（決まり20） |
| 手順、仕組み、流れ | 図（フロー、構成図） |
| 事実の列挙、活動報告、総括 | 見出し＋箇条書き（1列） |
| 反省や判断の論証 | 文章（段落）。太字は各段落の冒頭句だけ |

図にする必要がないものを図にしない。表やマトリクスで「構造化してふわっと逃げる」のは却下された。

## 対応表（候補の例）

| 内容の種類 | 候補の形式 | 却下された形式と理由 |
|---|---|---|
| 市場規模（どれだけ大きく、どこまで取れるか） | `tamSamSom`。入れ子の円と、対象・根拠・金額の3行。不明な値は仮値で埋めて（仮）を付ける | 調査会社の推計の開きだけを描く → 読み手の問いに答えない。世界市場の金額だけ → 取れる範囲が分からない。比例した円や棒 → 桁が違いすぎて読めない |
| 市場の成長（伸びるのか、どれくらい確かか） | `colBars` の `cagr`。0 から始まる縦棒に年ごとの実績を並べ、最初と最後の棒を矢印でつなぎ「年平均 +x%（期間）」を書く。対数軸・出どころの違う推計の重ね合わせ・推計の幅の帯は使わない | 2026年の点だけを並べる → 成長が見えない |
| 選択肢の評価（3〜4案×評価軸） | 測れる軸は、指標ごとの棒（`metricBars`）。語で比べる軸は、小さな表（`compareTable`。同じ種類の値だけ）。結論はリードか表の横 | 数値・語・丸を混ぜた大きな表 → 列を縦に読めない。表の中の判断の行 → 種類の違う行。罫線・帯の表、◎○△×だけ → 根拠が見えない |
| 効果と手間の釣り合い・施策の優先度 | `matrix2x2`（ペイオフ: 横＝手間、縦＝効果、狙う象限を1つ強調） | 表で釣り合いを読ませる |
| 決裁の依頼 | 決める額と内訳（棒か表）、決めた後の次の一歩（いつ・誰が・何を）を主役の図にする。決める額は `focusValue`。根拠の図を背面に敷くなら、前面の箱で隠さない（2026-11-25 に改めた。`decisionPage` は使わない） | 太字の箇条書きだけ、計画の図を薄く敷いて箱で一部を隠す、内訳をノートに回す |
| ベンチマーク（多数の対象×指標） | `compareTable`。自分の行を帯で示し、値の右に順位の列 | 塗りブロックのタイル |
| 選択肢・媒体の比較 | `compareTable`。セルは数値・評価の丸だけ（文を入れない。決まり20）。構成案が行の順を決めていないときは、使う行を上、使わない例を下にしてよい（決めているときは構成案の順のまま、強調で示す）。性質の違う対象は列を分け、同じ値は列をまたぐ1セル | 特徴を行に並べた比較表（仕組み／実績／使い方）→ 何を読めばよいか分からない |
| 状態の変化（項目ごと） | `stateMap`。1枚のマップで、項目の描き方を状態ごとに変える（例: 身についた／経験した／以前から） | Before 枠と After マップの2形式 → 左右で構造が違い前後が分からない |
| 状態の変化（同じグラフの値） | 前ページと同じ位置・大きさ・縦軸最大で After を1枚描き、ページ送りで差を見せる | 左右に並べ直す |
| 計画・スケジュール | `projectGantt`。計画だけを、グループと作業の2段で10〜20行。帯は同じ太さ。リードが言う作業の帯だけ強調の色 | 3〜4行の区分だけのガント → 計画として粗い。遅れ・ひし形・今日の線・会議の線・見る所と関係ない色分けを描き込む → 要素が多すぎて見づらい（遅れは別ページで前面に重ねて言う） |
| 経緯（時系列） | ガント。行＝区分色、列＝月、年度と四半期の目盛り、節目は赤の縦破線＋ひし形。上位の行を最上段に置き、下で詳細化。出来事・判断・対象は層を分ける | 目的外の行（競争環境など）を足す。活動・状態・判断を同じ行に混ぜる |
| 予定と実績（遅れ） | ガントで、行の上に予定の破線の細い帯、下に実績の塗りの帯（`plan`）。暦の年月で書かれた内容は月の目盛り（`axis: "month"`）。遅れの主因の行だけ濃紺、最大の分岐点だけ太い赤の破線。帯の外の短い注記（「3か月遅れ」）は `notes` | 予定と実績を別の図や表に分ける。年度・四半期の目盛りで月単位の遅れを読ませる |
| 月次の俯瞰 | 同じ月の横軸に帯を縦に積む1枚（概要→見立て→活動→外部環境→意思決定→体制・投資・工数）。月は等幅、空白の月も残す。期間は線、出来事は点 | 帯ごとに別の表に分ける → 縦1列で照合できない。外部の変化をスパンで描く → 外部の変化は点。「未設定」と書く |
| 文字の多い時系列 | 月を行に取った表。判断の場がない期間は空白の帯 | 横軸の線表に文字を詰める → 読めない |
| 参入・出来事の時期 | `eventTimeline`。年月の軸上に点、真下に名前。近いものは3段にずらし細い引出線。自社だけ濃紺太字 | 番号つきの丸＋下に名前の一覧 → 対応が直感的に分からない |
| 実測の所要時間 | 実時間に比例した帯（色＝担当）。事例を同じ縮尺で縦に並べ、日単位に丸め、帯の中に白字 | 時分単位、合計値、左下の注釈 → なんとなくの粒度で足りる。特定の部署だけが悪い印象を出さない |
| 繰り返しの見込み | `cycleDiagram`。円を工程の数に分けて回る向きを示す。箱のループ図と赤の戻り矢印に「n回以上繰り返す見込み」 | ■と数字で回数を示す → 本当にその回数をやる印象が出る |
| 並行して重なった問題 | 左右のガント。左＝実際（重なりを赤枠、未着手は破線の空の帯）、右＝あるべき姿（階段状、間に赤破線のゲート） | 縦の流れ図 → 分かりづらい |
| 原因・要因の分解 | `logicTree` の多段の樹形図。左の問題から右へ、1つのノードから2〜3本ずつ広がる（問題→直接の原因→根本の原因、1→3→9）。手を打つべき根本の原因だけ赤枠 | 原因2つだけのツリー → 浅い。縦の「なぜなぜ」の連鎖 → 浅い一般論に見える。中段に分類だけの箱（「判断の誤り」など）→ 不要 |
| 原因の所在 | 原因×所在のマトリクス。原因がある所だけ濃い塗り、ない所は破線の空枠。全部は埋めない。対策も同じマトリクス・同じ寸法 | 抽象的な分類軸（「動機・前提・歯止め」）→ 聴き手が知りたいのは手当て先 |
| 問題の核心（両立できない2つ） | `matrix2x2`。2軸の散布図。到達できない両立領域を破線の丸 | 資源の軸（資金・技術・人…）の表 → それっぽいものを並べず核心に絞る |
| 手順・作業の流れ | `processFlow`（工程ごとの詳細を行で積む）。受け渡しが主題なら `swimlane`。左→右の箱。各手順の要所に URL。戻る矢印だけ赤、進む矢印は紺。画面は効く所（2〜4か所）だけ | 読ませる手順表、手順図の下の別表 。全手順に画面 |
| 漏斗状の段階 | `funnel`。中心をそろえた台形の段（目安の比率）と、右に段ごとの説明の列 | 実績値を入れて赤で強調 → 「今回が悪かった」印象は不要。罫線の表 |
| ルールと例外 | `points`（ルールを要点に、例外を根拠の1文に）。マトリクスに文を積まない（決まり20） | マトリクスの下に別の箇条書きで列挙 |
| 制度・規定への組み込み | 社内の規定図を原寸のまま埋め込み、白の半透明で薄くし、赤の縦破線のゲートと詳細の箱を重ねる。部署内の運用は該当行に1行足して紺枠、その行だけ元の濃さに戻す | 規定図を濃いまま背景に。詳細を右下の1つの箱に → どこに組み込むか見えない |
| フェーズゲート | 行を貫く赤の太い破線。位置は全ページ共通の座標 | 表の1行として置く → ゲートは行ではない |
| 段階×観点の全体像 | `roadmap`。段階の駅と、駅ごとの次へ進む条件の値（4つまで）、下に資金や体制の帯。持ち帰るのが進むか決める値なら、その値を大きく置く | 段階×観点の表（`journeyMap`）→ マス目に文を積むと、全部読まないと分からない（決まり21） |
| 費用と期間 | 横幅＝期間、高さ＝月あたり費用の面積棒（上に総額と月額） | 総額の積み上げ → 期間の長い段が大きく見える |
| 投資額の推移 | 四半期のウォーターフォール（増分は灰）＋右端の累計棒だけ目的別の色 | 支出明細表、費目別（人件費・委託費）→ 判断材料にならない |
| 評価（星取） | ◎○×（△）。強い印だけ濃く太く、弱い印は灰。評価の軸ごとに1行 | 評価5項目・3段階 → 差が出ない。評価表を別ページに → 作例から離れる |
| 配分（構成比） | 100%積み上げ棒、棒の高さを総量に比例。区分は5つ程度、はっきり違う色、凡例は積みと同じ順。棒の直下に同じ色の■で注力の説明 | 費目別 → 見たいのは注力の実態。近い色の7区分 → 色が分からない。凡例と積みの順が逆 |
| 配分の推移 | `ribbonBars`。積み上げ棒の同じ区分を隣の期と帯でつなぐ。区分名は右端の棒の横に1回、凡例なし。棒の上の値は、リードが言う数値（合計、主役の区分の割合など）1つだけ | 数値の表、高さを100%にそろえて総量の変化を消す |
| 数値の推移と目標 | 線・点・目標線を1つの部品にして複数ページで共有。自社＝濃紺実線と塗りの点、他社＝灰の線と白抜きの点、見込み＝点線 | ページごとに線の描き方が違う  |
| 2つの率の比較（自社と全体、市と県） | `colBars` の対の棒。主役の系列を濃紺、相手を灰。正負は0の線の上下へ | 主役の系列だけを描き、比べる相手をリードの文だけで言う |
| 内訳と合計の推移（社会増減・自然増減と人口増減） | `colBars` の3系列。合計の系列を主役（濃紺、値を太字） | 内訳と合計を別の図に分ける、`waterfall` で代用する |
| 項目ごとの正負（地区別の増減） | `hBars`。0の線から左右へ、全体の行を最上段に置いて間を空ける。まとめの注記は `groups` | 縦棒で項目名を斜めにする |
| 量・累計の推移 | 累計の単色棒（値は太字、直下に期のラベル）。規模は1本の折れ線、見込みは白抜きの点 | 区分を色分けした新規数 → 量が見えればよい。仮値と明示せず仮定を重ねた試算の折れ線 → 空想の値に見える |
| 示唆・提言・申し送り | `points`。言い切りの要点（太字）＋根拠の1文、右に「根拠 P.n」 | 長文の箇条書き、要点と説明を同じ段に詰める |
| 事実の列挙（活動・総括・知見） | 言いたいことが1つなら、その語か数値を大きく置く。並べて挙げること自体が目的なら `bullets` で見出し＋箇条書き（1列）。区分が構成案にあれば小見出しにする。無ければ足さない | 矢羽＋マトリクス、ガント、左右ブロック、罫線のリスト、構成案に無い分類ラベル |
| 章の全体像 | 前の図（経緯ガントなど）を同じ位置に描いて白で薄く覆い、赤丸番号と赤枠の吹き出しを重ねる | 新しい図を起こす |
| 問題の構造（人と道具） | 人のアイコンの周りに道具・アプリを配置。使っているものは実線、使っていないものは点線・灰 | 囲みブロックの流れ図、分岐フロー図 |
| 仕組み・ノウハウ | `archDiagram`。実際に組んだ構成のアーキテクチャ図＋該当箇所に前面のテキストボックス。ファイル構成はディレクトリツリー＋右に手順 | STEP1〜4の手順図 → 教科書的 |
| 洗い出し（ブレスト） | 付箋のボード（帯×まとまり）。文字が小さくても量を優先 | 傾けた付箋 |
| 整理済みの能力・要件 | `stateMap`。区分ごとの枠に白箱を縦に並べるマップ | 付箋 → ブレストとは別物 |
| 指標の分解 | `kpiTree`。左の指標を右へ、× ＋ で子に分ける。各ノードに名前・値・増減。増えた・減った所1つだけを赤枠（または強調の色）で、増減を 36pt | 文の原因の樹形図に数値を混ぜる（つながりが見えない）、指標を棒で並べるだけ |
| 役割の分担 | `raciTable`。作業×担当に R・A・C・I の印だけ。A は1作業に1人。A がいない・2人いる行を赤枠 | セルに文で役目を書く表、印を色だけで分ける（凡例なし） |
| 体制 | `orgChart`。責任者→部署→チーム→メンバーの樹形。同じ人アイコンを人数分（色は統一）、下に役割名 | 役割別のアイコン、一部だけ灰色 |
| 同じ／違う | 記号「≠」（赤枠）「＝」（紺枠）を大きく | — |
| サマリー | 話して見せる資料には置かない。送って読ませる報告書は、冒頭に要約を1枚置いてよい（`summary`：決めてほしいことを上に1つ、根拠を下に2〜4個、線でつなぐ。`points` の羅列にしない）。末尾のまとめは置かない | 問題／原因／対策の表、枠と矢印のプロセス図 |
| 新しい事業・製品のコンセプト（初見の聞き手） | 一言を中央に大きく出すページ（`concept`）から入り、仕組み・比べる図は次のページ（2026-11-25） | 1枚に流れ・比較・示唆を詰める、いきなり仕組みの図から入る |
| 過去資料の再掲 | 原文のままの画像を枠いっぱいに | 描き直す |

## 迷ったとき

- 「全体像」を求められたら、1次元のフローや3〜4並列のパネルではなく、観点×段階の2軸を疑う。
- 「3つの価値」「4つのポイント」と先に数を決めて並べない。伝えたい1文から対比軸・境界・順序を取り出して形式を選ぶ。
- 同じ役割のページが既にあるなら、新しい形式を考えずに同じ部品で描く。
- 同じデータ・議題に前のページで触れているなら、形式を選び直さない。同じ図を背面に敷き、前面にメッセージボックスか吹き出しを置く（`echo`＋`messageBox` / `callout`）。
